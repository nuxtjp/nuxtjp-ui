# 一次情報の追跡方針

## 目的

デジタル庁の資料を推測や二次情報で取り込まず、参照した版、判断、実装、試験を再現可能にします。更新の検知と採用判断を分離し、予期しない UI 変更を防ぎます。

## 情報源

`upstream/sources.lock.json` は、DADS 文書、コンポーネント索引、アクセシビリティ指針、利用上の注意、公式パッケージ、サンプル実装、ダッシュボードガイドを別々の版軸として記録します。公式 URL 以外を規範的な根拠にはしません。

2026-10-23に確認した版の軸:

- 観測・レビュー済み文書／Figmaは2.18.2。実装基準と49部品の採用状態は2.16.0のまま別に保持します。
- 公開tokens 2.1.0の対応表は2.18.1までで、文書2.18.2との差を明示します。直接のruntime依存には追加しません。
- 利用する公開theme plugin 2.0.0の対応表は2.18.2までです。package manifestとの版の一致を検証します。
- HTML／Reactは固定headの全ファイル差分をレビューした参照資料です。公式Vue/Nuxt実装や製品全体の適合証明とは扱いません。

[テーマv2レビュー](upstream-reviews/2026-10-23-theme-v2.md)に、適用判断・ライセンス・公開artifactと試験を記録します。
upstreamの互換性表は、個別Vue部品や利用製品のアクセシビリティ認定ではありません。

## 更新フロー

1. `node scripts/check-upstream.mjs` で公開版・コミット・本文標識を照合する。
2. 差分または取得不能を `review-required` として記録する。
3. 一次資料の変更箇所、ライセンス、破壊的影響を人が確認する。
4. 要件 ID、対象コンポーネント、実装、試験、移行案を更新する。
5. レビュー後にだけ lock の期待値と確認日を更新する。
6. 試験証跡が揃った項目だけ `verified` にする。

スクリプトはファイル、依存関係、適合状態を変更しません。差分があっても自動採用しません。

## 要件状態

| 状態 | 意味 |
|---|---|
| `not-assessed` | 適用性を未判断 |
| `planned` | 適用するが実装・証跡が未完了 |
| `implemented` | 成果物とテストが存在 |
| `verified` | 要件ごとの検証証跡をレビュー済み |
| `exception` | 理由、リスク、代替策を承認済み |
| `not-applicable` | 適用外の根拠を確認済み |

## 変更の承認条件

- 一次 URL と参照箇所が特定されている。
- 利用素材のライセンスと加工表示が確認されている。
- 管理LayerやCoelaへ基礎themeと汎用UI責務を漏らしていない。
- キーボード、読み上げ、拡大、色以外の手掛かりを確認している。
- 状態を上げる場合は成果物、テスト、証跡が存在する。

## 非認定の表示

本パッケージは NuxtJP による独立した派生実装です。「デジタル庁公式」「認定」「完全準拠」と表示しません。実装済み範囲は要件カタログとコンポーネントカバレッジで限定して表現します。

## 検知済みで未採用の上流差分

2026-10-20の監視は、上流文書2.18.1とtokens/HTML/Reactの変更を検知しました。
これはネットワーク障害や実装CIの失敗ではなく、要レビューの検出結果です。
[確認記録](upstream-reviews/2026-10-20.md)に範囲と受入条件を分離しています。
この観測だけで、既存の期待値・確認日・実装基準や適合状態は更新しません。

固定した2.18.1差分の適用判断は[2026-10-23受入記録](upstream-reviews/2026-10-23.md)を参照してください。
このレビューでは既存runtimeへの移植は不要と判断し、候補のplanned状態と監視期待値を保持しています。
その後に検出した2.18.2／tokens 2.1.0／theme 2.0.0は別のレビュー対象です。

その後の2.18.2／tokens 2.1.0／theme 2.0.0は[別レビュー](upstream-reviews/2026-10-23-theme-v2.md)で扱います。過去の2.18.1記録は当時の判断として保持します。
