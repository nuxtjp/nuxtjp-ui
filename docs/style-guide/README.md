# NuxtJP UI スタイルガイド

## 位置付け

このリポジトリは、デジタル庁デザインシステム（DADS）を参照した独立の Nuxt 実装です。デジタル庁の公式実装・認定製品ではありません。DADS は共通の土台であり、サービス固有のスタイルガイドを別途定めるという一次情報の方針に従います。

- 基準: [DADS v2.16.0](https://design.digital.go.jp/dads/)
- 作成方法: [スタイルガイドの作成方法](https://design.digital.go.jp/dads/guidance/style-guides/)
- コンポーネント: [DADS コンポーネント](https://design.digital.go.jp/dads/components/)
- ダッシュボード: [実践ガイドブック](https://www.digital.go.jp/resources/dashboard-guidebook)

## 責務境界

このパッケージが所有するもの:

- Nuxt UI の導入、DADS theme、セマンティックトークン
- Nuxt UI に渡すセマンティックトークンと視覚階層
- 読取状態、ページ見出し、指標群、コピーなどの再利用パターン
- キーボード操作、フォーカス、ラベル、読み上げの実装方針
- 一次情報、要件、実装証跡、例外の追跡方法

管理Layerが所有するもの:

- 管理画面のレイアウト、スキップリンクの配置、ナビゲーション枠
- route metadataからのパンくず、タイトル、選択状態
- 管理状態の複合表示

利用アプリケーションが所有するもの:

- 業務用語、メニュー構成、権限、データ取得、更新操作
- 状態の判定、エラー原因、復旧手順、監査イベント
- 個人情報・機密情報の表示可否とマスキング
- ページ単位のアクセシビリティ試験と公開判定

Coela は後者だけを実装し、色、余白、汎用状態表現を複製しません。

## 画面構造

1. 最初に本文へのスキップリンクを置く。
2. ヘッダーにはサービス識別と全体操作だけを置く。
3. ナビゲーションと本文を別ランドマークにする。
4. ページごとに一つの主見出し、目的、対象者、更新時点を示す。
5. 一覧から詳細へ段階的に情報を開示する。
6. 状態と操作を近接させ、復旧不能な操作は無効理由を示す。

## 状態モデル

一つの曖昧な「ステータス」にまとめず、次を分けます。

| 軸 | 例 | 所有者 |
|---|---|---|
| 通信 | 未接続、接続中、接続済み | 接続アダプター |
| ライフサイクル | 未設定、設定済み、停止中 | 業務アプリ |
| 健全性 | 正常、低下、障害 | 監視サービス |
| 操作可能性 | 実行可、要認可、ブロック | ポリシー／業務アプリ |

色だけで状態を伝えず、短いラベルと補足を併記します。未取得と値がゼロの状態も区別します。

## ダッシュボード

ダッシュボードを作る前に、目的、対象者、判断、行動、データ源を定義します。各指標には観測時点、鮮度、取得不能状態を表示します。グラフは比較・推移・構成・関係の目的から選び、同等の表または文章要約を用意します。

## アクセシビリティ

DADS の採用だけでは適合を保証しません。コンテンツと運用を含むページ単位の責任は利用サービスにあります。

- 見出し、ラベル、関連付け、ランドマークを意味に沿って実装する。
- 全操作をキーボードで完結させ、フォーカスを視認可能にする。
- 文字・非文字コントラストとターゲットサイズを用途ごとに確認する。
- 動的更新、エラー、読み込み状態をテキストと支援技術へ通知する。
- 公開前に JIS X 8341-3:2016 AA と WCAG 2.2 A/AA のページ試験を行う。

自動検査は補助であり、キーボード、拡大、読み上げ、認知負荷を含む手動確認を置き換えません。

## 変更規則

一次情報の更新検知は実装へ自動反映しません。`upstream/sources.lock.json` と要件カタログをレビューし、影響、実装、試験、証跡を揃えた後に状態を更新します。現在の対応状況は [適合状況](../conformance/status.md) を参照してください。
