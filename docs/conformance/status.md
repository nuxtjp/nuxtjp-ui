## 現在の主張範囲

- 一次情報、要件、49 コンポーネントの採否を機械可読で追跡する。
- Nuxt UI派生themeと汎用表示部品をNuxt moduleとして提供する。
- 管理レイアウトとCoelaの業務実装から基礎UI責務を分離する。
- 更新は検知のみ自動化し、採用と適合状態は人のレビューを必須とする。

これは DADS 全体への適合認定ではありません。公式 Vue/Nuxt 実装は存在しないため、採用コンポーネントごとに意味、操作、アクセシビリティを再検証します。

自動 a11y 検査は導入後も補助証跡として扱い、上記の手動確認を置き換えません。

## 検証方法

```sh
node scripts/verify-compliance.mts
node scripts/check-upstream.mjs
```

1つ目はmodule内の参照、成果物、カバレッジ、互換性差分を確認します。2つ目は外部の一次情報を読み取り、差分を `review-required` として返します。外部検査はlockや実装を書き換えません。
